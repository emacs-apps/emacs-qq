* 阅读约定

本手册描述 monorepo 当前主线。最短启动路径和源码开发命令见
[[file:../README.org][README]]；原生服务的构建、持久化和协议实现见
[[file:../../../ntqq-rs/README.md][ntqq-rs]]。

按键表未特别说明时指 Emacs state。Evil normal／motion state 的差异在
[[*Evil][Evil]] 一章列出。菜单按当前对象的能力启用动作；看到菜单不代表拥有服务端权限。
~C-h m~ 查看当前模式，~C-h k~ 检查某个按键最终绑定。

客户端只连接原生 Gateway，不提供 OneBot、NapCat 或“切换后端”设置。
QQ 频道目前没有用户入口。普通私聊和群聊、账号管理、联系人、媒体与通知是本手册的
操作范围。

* 准备与首次连接

** 工作区与依赖

当前工作区的 Appkit 需要 Emacs 32 或更新版本。图形媒体使用 Appkit／video 的本地
模块和 Canvas；wdoom 的完整工具链要求见 [[file:../../../wdoom/README.org][wdoom README]]。
不要把 qq.el 的最低 Emacs 版本误当成整个工作区的最低版本。

从 monorepo 根目录准备并启动独立配置：

#+begin_src sh
./wdoom/bin/wdoom-prepare --byte
./wdoom/bin/wdoom
#+end_src

prepare 只使用工作区登记的源码，生成独立的加载快照和原生产物。它也会准备
browser-session helper，但不会启动 QQ 服务或连接账号。源码改变后需要重新 prepare
并启动新进程；已有进程不会自动改用新的快照。

不用 wdoom 时，使用 [[file:../../emacs-dev/dev-registry.el][工作区 registry]] 中的源码路径与包依赖，
从公共入口 ~(require 'qq)~ 载入。不要只复制 ~qq.el~：其余 Lisp 文件和
~qq-face-names.json~ 都属于包。browser-session 的 Emacs 代码与 helper 应来自同一
版本；构建和路径选择见 [[file:../../browser-session/README.org][browser-session README]]。

其他按需工具：

- ~qrencode~：绘制手机确认 challenge 中返回的二维码；
- ~ffmpeg~：MP4 发送缩略图和部分动画转换；
- 支持 Emacs notifications 的桌面通知服务；
- Evil：可选，包内绑定不要求 evil-collection。

** 原生服务和认证

原生服务独立启动，可以在没有登录账号时运行。当前 JSON 配置要求 schema 4，
~auth_token_file~ 和 ~runtime.services.credentials~ 必须配置。token 与凭据加密
master key 是不同秘密文件；不要直接把旧 schema 2 示例当成可运行配置。
存储目录和配置边界见 [[file:../../../ntqq-rs/README.md][ntqq-rs README]]。

从 monorepo 根目录校验本地配置，再启动：

#+begin_src sh
cargo run --manifest-path ntqq-rs/Cargo.toml -p nt-gateway -- \
  --config /absolute/path/to/gateway.json --check
cargo run --manifest-path ntqq-rs/Cargo.toml -p nt-gateway -- \
  --config /absolute/path/to/gateway.json
#+end_src

配置内的相对路径相对 JSON 所在目录解析；运行策略不从环境变量或额外 CLI 参数读取。
不要把服务进程的生命周期绑在某个聊天 buffer 或登录命令上。

客户端默认地址为 ~ws://127.0.0.1:3002/~。~qq-server-auth-token-file~ 指向服务端使用
的同一个 token 文件：单个不含空白的 token，至少 32 字节。Unix 下不允许组或其他用户
读取，通常使用 ~0600~ 权限。token 在打开连接时读取，不应写进源码、日志或共享配置。

wdoom 默认使用状态目录下的 ~qq/service-token~。未覆盖状态目录时通常是
=~/.local/state/wdoom/qq/service-token=；~WDOOM_STATE_DIR~ 和 ~XDG_STATE_HOME~ 会改变
实际位置。wdoom 不自动导入旧配置的凭据。其他 Emacs 配置中，包的默认位置是
~user-emacs-directory~ 下的 ~qq/service-token~。

如果地址或 token 路径不同，在个人配置中设置：

#+begin_src emacs-lisp
(setq qq-server-websocket-url "ws://127.0.0.1:3002/"
      qq-server-auth-token-file "/absolute/path/to/service-token")
#+end_src

当前 Gateway 仅监听 loopback，WebSocket listener 本身没有 TLS。远程使用应通过
SSH 隧道，或明确配置外部 TLS 终结与受保护网络；~wss://~ 不是服务直接提供的监听模式。
仍需认证，不要公开 token，也不要把无加密 WebSocket 暴露到不可信网络。

** 第一次使用

1. 独立启动原生服务，确认地址和认证文件。
2. 在 Emacs 执行 ~M-x qq~；wdoom 对应 ~SPC a q~。
3. 选择已在线账号，或进入账号登录流程。
4. 在该账号的最近会话页用 ~RET~ 打开一个聊天。

连接服务与账号上线是两个阶段。账号管理页可以为空，账号也可能正处于登录挑战或
离线阶段；空列表不一定表示 WebSocket 连接失败。

只想查看账号管理页而不连接时，使用 ~M-x qq-root-open-gateway~，wdoom 对应
~SPC a Q~。~qq-connect~ / ~qq-disconnect~ 只连接／断开这个 Emacs 客户端。

* 账号与运行状态

原生服务管理账号登录、重连、停止和移除；Emacs 为每个稳定 ~account_id~ 保存独立的
账号视图和状态。多个账号的最近会话、聊天和资料页可以同时存在。

选择账号只改变从无账号上下文发起的新命令的默认目标。已经打开的聊天仍属于原账号，
不会因为切换选择而向另一个账号发送消息。

| 操作 | 用户入口 | 边界 |
|------+----------+------|
| 日常启动 | ~qq~ | 连接服务并进入账号选择／登录流程 |
| 账号管理页 | ~qq-root-open-gateway~ | 只打开管理视图 |
| 登录 | ~qq-login~ | 驱动账号登录挑战 |
| 选择账号 | ~qq-account-select~ | 改变默认账号，不改绑现有聊天 |
| 启动账号 | ~qq-account-start~ | 创建运行中的 Native Session，随后仍需登录 |
| 停止账号 | ~qq-account-stop~ | 关闭当前 Native Session，保留账号槽与 EasyLogin |
| 退出登录 | ~qq-account-logout~ | 请求 QQ 退出；成功后删除 EasyLogin，保留账号槽 |
| 永久移除 | ~qq-account-remove~ | 删除已停止的账号槽和对应登录记录，不删除共享设备资料 |
| 刷新 | ~qq-refresh~ | 刷新服务／账号投影；未连接时开始连接 |
| 断开客户端 | ~qq-disconnect~ | 不停止、不退出服务端账号 |
| 重置客户端 | ~qq-reset-session-state~ | 清空当前 Emacs 的 QQ 状态并关闭所属视图 |

重置是破坏性的本地操作：传输、通知、媒体任务和账号相关缓冲区会被关闭，先保存需要
保留的草稿。它不是服务端账号退出，也不等同于删除磁盘缓存或服务端消息。

停止、退出登录和移除有独立确认。退出失败会保留登录记录，不把失败伪装成成功；
服务重启只恢复已停止的账号槽，不自动让账号上线。

** 只读文件导出

账号菜单 ~? A F~（Evil 为 ~g a A F~）打开 FileBridge 管理页；服务需提供相应能力。
~g~ 刷新状态，~e~ 明确选择 Gateway 主机的绝对导出目录并确认风险，~d~ 禁用导出。
它不是普通文件聊天，也不会因为附加文件而自动开启。原生弱认证可能被网络对端伪造，
只能导出非敏感目录；自签名 TLS 不能消除该认证风险。

** 登录挑战

登录选择器包含已管理账号、可用的 ~Quick login~ 记录和 ~Add QQ account~。
在线账号直接选中；快速登录复用已有 EasyLogin，但仍可能要求手机确认。
密码登录遇到验证码时，客户端使用 browser-session 启动隔离浏览器，完成受支持的
QQ 验证页面后自动提交与当前 challenge 匹配的 proof。手机确认 challenge 返回二维码
URL 时用 ~qrencode~ 展示；这不是一个另外承诺可用的独立扫码登录入口。

不需要从 DevTools 手工复制 ticket，也不要把浏览器 cookie 当作原生登录凭据。
取消、超时、账号关闭或 challenge 替换都会让旧结果失效。默认验证码超时是
~qq-login-captcha-timeout~ 的 300 秒；浏览器、代理和 helper 路径在 browser-session 的
Customize 选项中设置。
取消前台登录交互不等同于停止服务端账号；需要停止时使用明确的账号生命周期命令。

* 最近会话与资料

** 最近会话

账号最近会话页显示会话摘要、时间、未读和提及状态。顺序采用原生服务的最近会话投影，
不在客户端中按名称重新排序。媒体缓存可用时，摘要旁可显示一行高预览。

| 按键 | 操作 |
|------+------|
| ~RET~ | 打开当前会话 |
| ~g~ | 刷新 |
| ~/~ | 按名称选择会话 |
| ~c~ | 联系人目录 |
| ~N~ | 群申请主箱与过滤箱 |
| ~a~ / ~i~ | 当前会话头像／资料 |
| ~I~ | 自己的资料 |
| ~u~ | 下一个未读会话 |
| ~n~ / ~p~ | 下一个／上一个可操作项目 |
| ~TAB~ / ~<backtab>~ | 在可操作控件之间移动 |
| ~?~ | 场景菜单 |
| ~q~ | 退出窗口 |

文字、头像和卡片中的链接是独立控件；~RET~ 或鼠标点击执行当前控件动作。

** 联系人和群成员

从账号最近会话页按 ~c~ 打开该账号的联系人目录。

| 按键 | 操作 |
|------+------|
| ~f~ | 好友目录 |
| ~G~ | 全部已加入群聊 |
| ~I~ | 不在最近会话中的群聊 |
| ~RET~ / ~m~ | 打开联系人或群聊 |
| ~i~ / ~a~ | 资料／头像 |
| ~w~ | 复制 QQ 号或群号 |
| ~t~ | 展开／收起分类 |
| ~n~ / ~p~ | 目录项目移动 |
| ~b~ | 返回最近会话 |
| ~g~ / ~q~ | 刷新／退出 |

用户资料页：~m~ 私聊、~l~ 点赞、~a~ 头像、~w~ 复制 QQ 号、~g~ 刷新。
群资料页：~m~ 群聊、~s~ 搜索成员、~o~ 群主资料、~a~ 头像、~w~ 复制群号。
成员搜索先取得完整群成员快照，再按名片、昵称、备注、QID 或 QQ 号做本地子串筛选，
最多显示 200 个结果，查询不能为空；不是服务端索引搜索或无限续页。

消息头的群头衔、群主／管理员标记和等级反映当前成员资料，不是发消息时的历史身份。
已过期头衔会隐藏；私聊或来源群未知的转发不会借用当前群的成员徽标。
资料字段取决于 QQ 隐私设置和服务返回值，客户端不猜测缺失字段。
群资料的 ~N~ / ~R~ / ~P~ / ~M~ 分别设置群名、备注、置顶和全员禁言；~S~ 打卡，
~@~ 查询 @全体配额，~L~ 退群。群成员目录的 ~C~ / ~T~ / ~K~ 修改名片、头衔或踢人。
这些是 Emacs state 的入口，动作仍需 QQ 授权；配额查询不等于输入区的 @全体补全。

** 群申请

从最近会话页按 ~N~ 打开该账号的申请页。主箱与过滤箱同时展示，但保留各自的身份。
~g~ 刷新；用 ~TAB~ / ~<backtab>~ 移到同意或拒绝按钮，再用 ~RET~ 执行。

未知事件与已处理记录可以阅读，但没有操作按钮。申请 sequence 保留为原始十进制
字符串；同意／拒绝操作不会猜测另一个申请箱或记录。

* 聊天：输入、发送与历史

** 时间线和输入区

聊天 buffer 上方是只读时间线，末尾是可编辑输入区。时间线单键只在输入区之外生效。
消息之间不额外插入空白行，正文中的换行和空行保持原样。同一发送者的连续消息可以
省略重复消息头，但每条消息保留自己的时间和发送状态。

| 输入区按键 | 操作 |
|------------+------|
| ~RET~ | 发送，或先接受／处理活动补全 |
| ~C-u RET~ | 插入换行 |
| ~C-c RET~ | 显式发送原文，不把未完成 token 当成待补全内容 |
| ~TAB~ | 提及／表情等补全 |
| ~C-c C-o~ | 输入菜单 |
| ~C-c C-a~ | 选择附件类型 |
| ~C-c C-f~ | 选择文件并判断图片、视频或普通文件 |
| ~C-c C-v~ | 剪贴板文件／图片 |
| ~C-c C-e~ | QQ 基础表情选择器 |
| ~C-u C-c C-e~ | 收藏表情选择器 |
| ~M-p~ / ~M-n~ | 当前会话的纯文本发送输入历史，不含结构化附件 |
| ~DEL~ / ~C-d~ | 按结构化对象边界向后／向前删除 |

时间线的 ~RET~ 优先激活按钮、引用或媒体控件；其他位置聚焦输入区。~C-c '~ 也可
聚焦草稿，但不会自动切 Evil state。附件、提及和表情是结构化输入对象，不应
用普通文本编辑把它们切成一半。发送失败时，若输入区还未被新草稿替换，客户端恢复
原草稿与附件。

~C-c C-k~、~ESC ESC~ 或 ~C-M-c~ 用于取消当前状态。取消回复只移除回复目标，保留
草稿；没有回复时的清空动作会改变草稿，执行前检查当前状态。

** 提及和表情

群聊输入 ~@~ 后，可按群名片、昵称、QID 或 QQ 号补全成员。只有选择得到的
结构化 ~at~ 段才会作为 QQ 提及发送；普通文本中的 ~@名字~ 不会被猜成提及。

- ~/~ 加表情名称：QQ 基础表情；
- ~/fav~ 加可选描述：收藏表情；
- ~:unicode_name:~：Unicode emoji；
- ~C-u C-u C-c C-e~：强制刷新收藏表情目录。

收藏表情选择器先打开，再异步加载目录和预览。加载中可筛选或用 ~C-g~ 取消。
失败与空目录是状态提示，不是可选表情；取消后到达的结果不会重新打开选择器。
输入区的成员／收藏补全遇到冷缓存时，首次触发可能只发起加载，完成后需再次补全。

~RET~ 遇到未解析的提及／表情 token 时会先补全或提示；要确实发送这些原始文字，
使用 ~C-c RET~。

*** 管理收藏表情

聊天中执行 ~M-x qq-chat-favorite-emoji-transient~，或从聊天场景菜单的
~F Favorite emojis~、附件菜单的 ~m Manage favorites~ 进入：

| 按键 | 操作 |
|------+------|
| ~a~ | 从本地图片添加收藏，不发送聊天消息 |
| ~d~ | 选择并删除收藏，执行前确认 |
| ~e~ | 编辑 QQ 云端注释；留空即清除 |
| ~m~ | 移到指定位置，~1~ 表示最前 |
| ~g~ | 从 QQ 刷新目录 |
| ~f~ | 选择收藏插入草稿 |

聊天记录中把光标放到具体图片卡片，进入消息的 ~Media~ 菜单，再按
~f Add to QQ favorites~；也可执行 ~M-x qq-chat-save-image-as-favorite~。
收藏使用原始图片资源，不使用缩略图或动图预览的转换版本。

注释会显示在选择器中并参与搜索。操作绑定发起聊天的账号；切换账号不会改变目标。
修改完成后，该账号已打开聊天的收藏列表失效，旧请求不能把已删除条目写回。
QQ 未明确确认的删除会提示为未确认，不冒充成功。服务未提供对应能力时，菜单项置灰。


** 附件

输入菜单的附件项和 ~C-c C-a~ 可明确选择图片、视频、普通文件、自动识别媒体、QQ
表情、收藏表情或剪贴板。剪贴板优先读取本地文件 URI，其次读取图像字节；macOS 还
支持 ~pngpaste~。给剪贴板命令前缀参数可强制按文件处理。

普通文件每次只发送一件，不能混文字、回复、其他媒体或多个文件；客户端不会自动
拆成多条来绕过限制。自动识别的音频／视频扩展不保证都能原生发送：语音目前要求
单声道 PCM WAV，视频要求 MP4。可以明确选择 ~file~ 作为普通文件发送。

原生视频发送只接受 MP4，并需要 ~ffmpeg~ 生成 JPEG 缩略图。视频正文和缩略图上传为
不同资源，不会把普通文件或缩略图当成视频正文。文件路径不会成为发送给其他用户的
消息文本。

** 手机／电脑文件会话

原生服务返回 DataLine 会话时，可以从最近会话页打开。它不是 QQ 频道，也不承诺
普通群聊的回复、提及或合并转发能力。文本目前限一个非空文本段、160 UTF-8 字节；
文件／图片每次一件，不能混文字。

** 历史与已读

~C-c g~ 刷新聊天。接近时间线顶部会请求更早历史；在围绕某条消息的局部窗口中，
接近底部且输入区空闲时可以请求更新历史。~qq-chat-history-auto-load-threshold~ 是
字符距离，不是消息条数；设为 ~nil~ 关闭自动边缘翻页。

回复预览可跳到原消息。目标未落库时，Runtime 按群消息序号或私聊引用的原始时间、
发送方和客户端序号直接补取目标附近的窗口，不从最新消息逐页搜索。按 ~x~ 或
~M-g x~ 返回跳转前的位置；历史群消息没有 QQ Message ID 时仍按 canonical 行定位。
已过期、被本地隐藏、存在歧义或缺少必要定位信息的目标会明确报错，不跳到相邻消息。

~C-c r~、~M-g >~ 或 ~M-g r~ 直接标记整个会话已读，不加载历史、不移动当前位置，
也不清空草稿。每次操作固定一个最新已读边界；操作期间到达的更新消息仍保持未读。
~C-c g~ 或 ~M-x qq-chat-return-to-latest~ 独立负责回到最新窗口。

默认 ~qq-auto-mark-read~ 为 ~t~：聊天按观察到的光标位置推进读位置；光标在输入区时
使用最新已加载消息。其他窗口的滚动观察也可能推进到其光标，但仅显示一个聊天
不等于立即把整个会话标为已读。

* 消息操作与转发

** 时间线按键

| 按键 | 操作 |
|------+------|
| ~r~ | 回复当前消息 |
| ~d~ | 删除方式菜单：再按 ~d~ 本地删除，或 ~r~ 请求 QQ 撤回 |
| ~m~ | 选择／取消选择，然后移到下一条消息 |
| ~U~ | 清空当前聊天的选择 |
| ~f~ / ~C-c f~ | 转发选中消息；没有选择时使用当前消息 |
| ~o~ | 当前消息操作菜单 |
| ~a~ / ~i~ | 发送者头像／资料 |
| ~h~ | 当前会话资料 |
| ~g~ | 跳到当前回复引用的原消息 |
| ~x~ | 返回消息跳转前的位置 |
| ~P~ | 戳一戳当前消息的发送者 |
| ~!~ | 选择并添加表情回应；已有回应 chip 可点击切换 |
| ~?~ | 聊天场景菜单 |
| ~q~ | 退出窗口 |

~C-c P~ 是聊天的戳一戳入口，~C-c i~ 打开当前会话资料。撤回与本地删除不同：
撤回请求 QQ，权限与时间限制由 QQ 判定；本地删除持久隐藏时间线消息，不影响服务端
或对方副本，后续重取历史也不会把它重新显示出来。

** 当前消息菜单

在消息上按 ~o~。菜单固定打开时的消息与视图，不会因为随后移动光标而操作另一条
消息；执行时仍重新校验该消息和账号视图是否有效。

常用子入口：~t~ 翻译、~i~ 发送者、~o~ 媒体，群消息按能力提供回应、精华和 ~T~
群待办。菜单中的转发只处理这一条消息，不消费时间线的已有选择。

** 选择与合并转发

选择依赖稳定消息身份而不是屏幕行号，刷新和加载历史不会把勾选移到另一条消息。
~m~ 选择、~U~ 清空，~f~ 打开转发流程；提交顺序始终按时间线排序，而不是点击顺序。

当前转发菜单的 ~m~ 把消息合并为一张聊天记录卡片，再选择私聊或群聊目标。
取消或失败保留原选择；成功只移除本次计划中的选择，不清除请求期间新增的勾选。

来源和目标必须是私聊或普通群聊。真实、未撤回、非服务消息必须有规范的服务端
~message_id~；尚未确认的 ~local-*~ 消息或仅有 sequence 的历史行不能转发。
校验失败时不改换来源、不回退成普通逐条发送。

** 翻译

~o t~ 显式翻译当前已加载消息的正文和可见提及，不下载附件、不展开合并转发，也不
发送回复预览或原始协议数据。译文显示在原文下方，可以隐藏、显示和重译；原文、
草稿和选择保持不变。

~appkit-translate-target-language~ 控制目标语言，~appkit-translate-backend-function~
控制后端。默认 Respond 适配器需要独立凭据，登录入口是
~M-x respond-auth-login-interactively~；翻译请求本身不会隐式打开登录流程。
滚动和重绘不自动翻译；消息编辑、撤回、删除或视图关闭后，旧结果不能进入新视图。

* 媒体查看与下载

静态图片直接显示缓存预览，不启动播放器。动图和动态 QQ 基础表情在可用的 Canvas
行内宿主中随可见性播放；视频需点击或按 ~RET~，~C-RET~ 可在独立窗口复用播放器。
没有 Canvas 时保留可用的静态预览，不把视频封面当成视频正文。

动态 QQ 表情按原始格式接入：

- Lottie JSON 由 ~video.el~ 的 dotLottie C 帧源直接播放，复用 Canvas 播放、
  暂停、定位和释放生命周期；首帧占位也是实际渲染的静态 Canvas。
  不生成 GIF，不调用 ~tgs2png~；QQ 基础表情显式循环，离屏后暂停。
- APNG 仍由 ~ffmpeg~ 生成 GIF；上限为 4 秒、20 fps、80 帧、128 像素宽、
  128 色调色板。这条兼容路径并非无损保留原始动画。

普通 PNG 解码器能显示 APNG 首帧，不等于能播放完整动画。已装 ~gst-libav~ 也不
保证所有 FFmpeg 格式都被接入 GStreamer。Lottie 通过播放器内部 ~appsrc~ 接入，
不要求系统安装 Lottie GStreamer 插件，也不会在滚动时启动转换进程。
资源未准备好时保留占位或失败状态，不通过无限重绘重试掩盖失败。

在媒体卡片上用 ~o o~ 进入媒体菜单：~o~ 打开、~D~ 下载或重试、~s~ 另存为、~y~
复制真实 URL，均按当前资源能力启用。原生语音只提供播放、暂停、恢复或重播，不支持
下载、另存或复制 URL；原生图片／视频／文件也不能凭空得到远端 URL。

语音播放器优先选择 ~ffplay~，再尝试 ~mpv~、~vlc~；视频仍由 Canvas／GStreamer
播放，不走这些外部音频播放器。播放另一条语音会停止前一条。

~M-x qq-media-clear-cache~ 会停止语音、取消媒体任务、清理内存缓存并删除媒体缓存
目录，不仅清除失败标记；主动下载目录不在其删除范围。基础 QQ 表情位图来自本机
QQ 资源目录，~qq-face-names.json~ 只提供名称映射，不包含整套位图。

* 通知与 mode line

通知与 mode line 都是可选全局模式，连接 QQ 不会自动打开它们：

#+begin_src emacs-lisp
(qq-notifications-mode 1)
(qq-mode-line-mode 1)
#+end_src

仅实时新消息触发通知，不为历史翻页补通知。桌面通知略作延迟以合并状态；目标聊天
正在当前聚焦 frame 的选中窗口中时不重复通知。静音会话默认不通知，原生 ~@我~ 可以
突破静音；~@全体成员~ 默认也可突破，可用 ~qq-notifications-at-all-breaks-mute~ 关闭。

私聊使用对方头像，群聊使用群头像加发送者头像。头像异步准备不会阻塞首次通知；
准备好后更新原通知，不增加历史项或重新计时。显式指定
~qq-notifications-extra-args~ 的 ~:app-icon~、~:image-path~ 或 ~:image-data~ 会保留
自定义图标，并关闭该通知的自动头像更新。

~M-x qq-notifications-history~ 查看进程内通知历史。模式关闭、通知关闭或账号重置后，
迟到的头像结果不会重新弹出旧通知。通知年龄、预览、延迟、超时和历史容量通过
~qq-notifications~ Customize 分组设置。

Mode line 默认显示 QQ 入口、未静音未读数和含提及的会话数；可点击相应部分导航。
样式选项是 ~qq-mode-line-format~ 和 ~qq-mode-line-string-format~。

* Evil

当 Evil 已加载且 ~qq-evil-enable-integration~ 非空时，包自动安装自己的 modal
bindings。默认初始 state 为 ~normal~，不要求 evil-collection。

#+begin_src emacs-lisp
;; 必要时在载入 QQ 之前设置。
(setq qq-evil-enable-integration t
      qq-evil-initial-state 'normal)
#+end_src

~qq-evil-initial-state~ 设为 ~nil~ 时不覆盖已有的 initial-state 选择。
要关闭包内集成，预先将 ~qq-evil-enable-integration~ 设为 ~nil~。

| 位置 | Evil normal／motion 按键 | 操作 |
|------+-------------------------+------|
| 根页、联系人、群申请 | ~gr~ | 刷新，保留原生 ~gg~ 等导航 |
| 会话／消息／联系人项目 | ~gj~ / ~gk~ | 下一个／上一个项目，不承诺管理页账号行跳转 |
| 根页、聊天 | ~g a~ | 场景菜单；裸 ~?~ 保留反向搜索 |
| 聊天时间线 | ~r~ / ~R~ | 回复／转发 |
| 聊天时间线 | ~m~ / ~a~ / ~gu~ | 选择／发送者头像／资料 |
| 聊天时间线 | ~D~ / ~dd~ | 本地删除并确认，不是 QQ 撤回 |
| 聊天 | ~g A~ | 复用原生 ~M-g~ 导航前缀 |

输入区 insert state 的 ~RET~ 与图形 Return 都处理发送／补全。带前缀参数的
~M-1 RET~ 插入换行，~C-c RET~ 显式发送原文。
按钮、引用和用户链接自己的 ~RET~ 绑定优先，不会被全局发送命令覆盖。
Normal state 聚焦草稿后，仍需用 Evil 自身的 ~i~ / ~a~ 进入编辑；时间线的单键 ~i~
不承担此入口。用户／群资料页没有统一的 ~gr~ 映射，可使用刷新按钮或对应 ~M-x~
命令；联系人／用户／群资料用 ~Zy~ 复制号码。

遇到按键问题，用 ~C-h k~ 检查当前 state 的最终映射。~M-x qq-evil-setup~ 可重新
规范化已经打开的 QQ 模式；不要用全局 ~RET~ remap 修复某一个聊天 buffer。

* 配置与数据位置

使用 ~M-x customize-group RET qq RET~ 查看全部选项。通知、Evil 与 browser-session
有各自的分组；以下只列常用设置。

** 连接与历史

| 选项 | 包默认值 | 含义 |
|------+----------+------|
| ~qq-server-websocket-url~ | ~ws://127.0.0.1:3002/~ | 原生服务地址 |
| ~qq-server-auth-token-file~ | Emacs 用户目录的 ~qq/service-token~ | 认证文件；wdoom 覆盖此路径 |
| ~qq-server-request-timeout~ | 30 秒 | 未响应请求的本地超时；~nil~ 关闭 |
| ~qq-server-ready-timeout~ | 10 秒 | 握手后等待权威 ready 快照；~nil~ 关闭 |
| ~qq-server-reconnect-delay~ | 3 秒 | 重连间隔 |
| ~qq-server-reconnect-max-attempts~ | ~nil~ | 不限次数；主动断开停止重连 |
| ~qq-history-fetch-count~ | 20 | 默认历史请求大小 |
| ~qq-chat-history-auto-load-threshold~ | 2000 字符 | 自动边缘翻页距离；~nil~ 关闭 |
| ~qq-login-captcha-timeout~ | 300 秒 | 浏览器验证码超时 |

请求超时不是 WebSocket 连接超时。重连计数在认证并收到 ready 快照后重置，不是仅在
socket 打开时重置。

** 聊天和媒体

- ~qq-auto-mark-read~：默认 ~t~，按聊天光标／可见消息推进读位置；
- ~qq-chat-show-recalled-messages~：默认 ~nil~，撤回消息不展示占位行；
- ~qq-chat-show-unread-divider~：未读分隔线；
- ~qq-chat-jump-history-count~：回复跳转使用的历史页面大小；
- ~qq-media-preview-image-height~ / ~qq-media-preview-image-max-width~：预览尺寸；
- ~qq-media-download-directory~：主动下载的位置；
- ~qq-media-cache-directory~：临时预览缓存。

root、联系人列表和聊天输入提示的单行头像使用 Appkit 的当前行高，不再保留固定头像列。
输入区附件、回复和 poke 的单行缩略图也由 Appkit 统一显示，宽高一起随文本缩放；
它们不使用多行媒体预览的尺寸选项。

系统表情的目录发现和 Lottie／APNG／PNG 资源选择属于 ~ntqq-rs~，不属于 Emacs。
客户端通过 ~system_emoji.resource~ 和 ~resource.open_local~ 获取原始资源，再复制到
自己的展示缓存；原生目录路径不会进入普通资源快照。此接口需要 Gateway 的 Resource
Store，但不要求登录账号；本地资源缺失时保留文字，不由 Emacs 下载 QQ 资源包。

需要覆盖资源位置时，在 Gateway 配置的 ~runtime.services.system_emoji~ 中设置
~cache_directories~（额外动态表情根目录）或 ~default_directory~（安装包内的静态表情目录）。
相对路径以 Gateway 配置文件所在目录为基准；不设置时由后端发现 LinuxQQ 缓存和默认安装目录。
“正在输入”尚未接入原生 chat-action 操作；保留的 ~qq-chat-send-typing~ 等选项不代表
当前会发送输入状态。

** 存储与隐私

不使用 wdoom 时，认证、下载和媒体缓存默认都相对 ~user-emacs-directory~。
wdoom 将持久状态和缓存分开，尊重 XDG 目录及自己的覆盖变量：

| 内容 | wdoom 相对位置 |
|------+----------------|
| 认证 token | state 下的 ~qq/service-token~ |
| 主动下载 | state 下的 ~qq/downloads/~ |
| 媒体预览 | cache 下的 ~qq/media/~ |
| video 缓存 | cache 下的 ~appkit/video/~ |
| 浏览器 profile | state 下的 ~browser-session/~ |

原生服务自己的账号凭据和消息存储由服务配置决定，不属于 Emacs 缓存。
~qq-reset-session-state~ 清理进程内状态，不等同于删除这些磁盘目录。

token 能控制服务端账号和业务操作，应按凭据保护。账号、群号、消息正文、消息 ID、
媒体 URL、浏览器验证码结果都可能泄露隐私；发布日志和截图前脱敏。
消息 ID 保留为原始十进制字符串，不能转换成浮点数或科学计数法。

* 排错

** 连接失败或持续重连

1. 检查原生服务是否运行、地址与端口是否一致。
2. 检查 token 文件可读、内容相同、长度和权限符合要求。
3. 区分 WebSocket 已打开、认证完成和 ready 快照已收到。
4. 检查账号的在线／挑战阶段；没有在线账号不等于服务未运行。
5. 用 ~qq-disconnect~ 停止重连，修正设置后再执行 ~qq-connect~。

不要靠反复重置账号来解决错误地址或认证文件，也不要把服务 token 改成公开可读。

** 发送、回复或转发指向错误消息

先检查服务和中间工具是否把 ~message_id~ 转换成了数值。雪花 ID 必须原样保持为
十进制字符串。尚未确认的发送占位与服务端消息不是两条独立消息，回执会晋升其身份。

修正协议或服务版本后，如需清除旧的进程内投影，先保存草稿，再使用
~qq-reset-session-state~ 并重新连接。不要扩大模糊匹配窗口隐藏身份缺失。

** 头像、表情或视频没有预览

检查缓存目录是否可写、QQ 位图目录是否存在、需要的转换工具是否可执行，以及图形
Emacs 是否具备 Canvas 和匹配的 video 模块。工作区更新后应重新 prepare 并启动新
进程，不从旧配置复制模块绕过兼容检查。

~qq-face-names.json~ 缺失会影响名称与补全；位图目录错误影响图片。预览失败要重试时
使用 ~qq-media-clear-cache~，不必先破坏性重置所有聊天。

** 通知没出现

确认已开启 ~qq-notifications-mode~。当前聚焦窗口显示目标聊天、静音、事件过旧或
预览设置都可能改变通知行为。用 ~qq-notifications-history~ 检查本地路径，再检查
系统通知服务与图标支持。

** Evil 按键不符合预期

检查 ~major-mode~、Evil state、~(featurep 'qq-evil)~ 和 ~C-h k~。Emacs state 的单键
~g~ 与 Evil 的 ~gr~ 不是同一绑定；~g a~ 打开应用菜单，裸 ~?~ 仍是反向搜索。
先确认载入了当前工作区版本，再使用 ~qq-evil-setup~，不要改全局发送或搜索按键。

注明 Emacs、原生服务、工作区提交和 Evil state；给出准确操作与预期／实际结果。
协议样例保留字段类型，但移除凭据和私人内容。项目入口：
[[https://github.com/emacs-apps/emacs-qq/issues][emacs-qq Issues]]。

* 开发入口

当前开发使用 jjosh 管理源码与依赖，使用独立 Emacs 和 ERT 验证，不使用 Eask。
源码测试命令、依赖登记、~dev-with-source-loads~ 和版本快照对照统一见
[[file:../README.org][README 的开发与验证章节]]。

不要在在线账号的日常进程中运行整套测试或卸载重载 QQ feature。
批处理能验证投影和状态边界，但媒体播放、补全弹窗、通知及真实服务操作仍需要在
相应运行环境中实际观察。
