在 Emacs 中使用 QQ：账号管理、私聊和群聊、联系人、结构化消息、媒体与桌面通知。
客户端通过 WebSocket 连接本 monorepo 的原生服务，界面使用 Appkit。

- 日常操作、配置和排错：[[file:docs/emacs-qq.org][中文用户手册]]。
- 原生服务的构建、启动和数据目录：[[file:../../ntqq-rs/README.md][ntqq-rs]]。
- 工作区 Emacs 的准备和启动：[[file:../../wdoom/README.org][wdoom]]。

* 先理解运行边界

原生服务是独立的长期运行进程，管理零个或多个 QQ 账号。Emacs 只是附着到服务的
客户端；断开连接或退出 Emacs 不会退出服务端账号。

每个账号有独立的最近会话、聊天、联系人和资料缓冲区。选择另一个账号只改变新命令的
默认目标，不会把已经打开的聊天改绑到别的账号。

当前主线只使用原生 Gateway 协议，不提供 NapCat、OneBot 或可切换的兼容后端。
历史版本留在版本控制中，不作为当前配置方式。

* 从工作区启动

以下 shell 命令都从 monorepo 根目录执行。

** 准备 Emacs

当前工作区的 Appkit 要求 Emacs 32 或更新版本。wdoom 还要求 Canvas、动态模块和对应
本地构建工具；完整前提见其 README，不要只按 qq.el 的 Emacs 版本下限准备环境。

#+begin_src sh
./wdoom/bin/wdoom-prepare --byte
./wdoom/bin/wdoom
#+end_src

prepare 使用仓库内登记的源码，在独立缓存中准备 Lisp、原生模块和 browser-session
helper；不下载 Emacs 包，也不连接 QQ。修改源码后重新 prepare，再启动新进程。
已有 Emacs 继续使用自己的快照，不会自动热替换。

** 启动原生服务并配置认证

先准备原生服务的 schema 4 JSON 配置，包括 ~auth_token_file~ 和
~runtime.services.credentials~。token 和凭据加密 master key 是不同的秘密文件，不能
写进 JSON 或提交到仓库；具体配置见 [[file:../../ntqq-rs/README.md][ntqq-rs README]]。

从 monorepo 根目录先校验，再启动服务：

#+begin_src sh
cargo run --manifest-path ntqq-rs/Cargo.toml -p nt-gateway -- \
  --config /absolute/path/to/gateway.json --check
cargo run --manifest-path ntqq-rs/Cargo.toml -p nt-gateway -- \
  --config /absolute/path/to/gateway.json
#+end_src

客户端默认地址为 ~ws://127.0.0.1:3002/~。token 文件由用户事先准备，服务不会自动
生成；内容是至少 32 字节的单个 token，Unix 下通常使用 ~0600~ 权限。

wdoom 默认读取状态目录中的 ~qq/service-token~，通常是
=~/.local/state/wdoom/qq/service-token=；~WDOOM_STATE_DIR~ 或 ~XDG_STATE_HOME~ 会改变
该位置。地址或文件位置不同，可在 wdoom 状态目录的 ~custom.el~ 中设置：

#+begin_src emacs-lisp
(setq qq-server-websocket-url "ws://127.0.0.1:3002/"
      qq-server-auth-token-file "/absolute/path/to/service-token")
#+end_src

不使用 wdoom 时，也可以在独立 Emacs 中加载工作区源码和依赖，随后 ~(require 'qq)~。
保留整个包目录，包括 ~qq-face-names.json~；源码路径登记在
[[file:../emacs-dev/dev-registry.el][dev-registry.el]]，不要借用旧包管理器缓存补齐工作区依赖。

** 单账号与多账号

默认使用单账号界面：~M-x qq~ 连接服务，直接进入当前账号的最近会话；需要登录时
继续登录流程。没有账号或保存的登录记录时直接开始新登录，不询问账号槽或标签。
尚未选定账号且存在多个候选时，会要求选择；当前 Emacs 进程会继续使用该选择。

- ~M-x qq-login-switch-account~：选择其他已保存账号，或使用不同 QQ 账号登录。
- wdoom 的 ~SPC a q~ 打开 QQ，~SPC a Q~ 更换账号。
- ~M-x qq-connect~ / ~qq-disconnect~（wdoom：~SPC a c~ / ~SPC a d~）：连接／断开客户端。

需要多账号并行界面时，在个人配置中开启：

#+begin_src emacs-lisp
(setq qq-multi-account t)
#+end_src

此时 ~M-x qq~ 打开账号管理页和选择器，~M-x qq-root-open-gateway~ 只打开管理页，
不主动连接。账号菜单提供管理、切换和添加账号；桌面通知会标注来源账号。
默认单账号模式只通知当前选定账号。切换模式不会停止、注销或删除其他 Gateway
账号，也不会删除已保存的登录记录；已有聊天仍保持原账号归属。

账号生命周期仍使用 ~qq-account-start~、~qq-account-stop~、~qq-account-logout~ 和
~qq-account-remove~ 等 ~M-x~ 命令；停止保留 EasyLogin，退出登录与永久移除另有确认。

* 日常使用

下表是 Emacs state 的常用入口。只读区的单键不截获输入区的普通文字。

| 位置 | 按键 | 操作 |
|------+-------+------|
| 最近会话 | ~RET~ | 打开会话 |
| 最近会话 | ~c~ / ~N~ | 联系人／群申请 |
| 最近会话 | ~g~ | 刷新 |
| 聊天时间线 | ~RET~ | 激活当前控件，或聚焦输入区 |
| 聊天时间线 | ~r~ / ~m~ / ~f~ | 回复／选择／转发 |
| 聊天时间线 | ~o~ | 当前消息操作菜单 |
| 聊天输入区 | ~RET~ | 发送，或先处理活动补全 |
| 聊天输入区 | ~C-u RET~ | 插入换行 |
| 聊天输入区 | ~C-c RET~ | 显式发送原文 |
| 聊天 | ~C-c C-o~ | 输入菜单 |
| 聊天 | ~C-c C-a~ | 选择附件类型 |
| 聊天 | ~C-c C-f~ / ~C-c C-v~ | 文件／剪贴板附件 |
| 聊天 | ~C-c C-e~ | QQ 表情选择器 |
| 聊天 | ~C-c r~ | 标记整个会话已读并跳到最新消息，保留草稿 |

消息之间不额外插入空白行；消息正文中的换行和空行保持原样。
同一发送者的连续消息可以省略重复的消息头，但保留各自的时间和发送状态。

携带原生预览信息的网址显示为 Appkit 链接卡片，保留标题、简介、图标和原始网址；
聊天与转发查看器使用相同渲染。点击或按 ~RET~ 才打开网页，不额外抓取网页生成
预览；没有预览信息的网址仍是普通文本。旧版服务曾存为 ~text.pb_reserve~ 的消息，
需更新服务并重新拉取对应历史，不能仅凭占位正文补造卡片。

群提及输入 ~@~ 后用 ~TAB~ 选择成员。基础 QQ 表情使用 ~/~ 加名称，收藏表情使用
~/fav~，Unicode emoji 使用 ~:名称:~。只有选中的结构化提及才会作为 QQ 提及发送。
冷缓存下，首次补全可能只触发加载，完成后需要再次按 ~TAB~。
斜杠补全与 ~C-c C-e~ 使用相同的原生表情构造器，选择时补齐表情类型和动画
pack/sticker 信息。原生目录尚未就绪时保留草稿并提示重试，不将未知表情强行
降级为普通表情。

收藏管理入口是 ~M-x qq-chat-favorite-emoji-transient~：本地图片添加、确认删除、
云端注释（留空清除）、排序和刷新。聊天图片的 ~Media~ 菜单提供
~Add to QQ favorites~，收藏原图而非缩略图；详见手册的“管理收藏表情”。

消息上的 ~o~ 菜单提供实际可用的动作：翻译、回应、精华、群待办、撤回、本地删除等。
单条消息菜单的转发不消费已有选择；时间线的 ~f~ 转发选中消息，结果按时间线排序。
权限和消息能力仍由原生服务决定。

普通文件每次单独发送一件，不能混入文字、回复或其他附件。自动识别为音频／视频的
文件仍需符合原生格式限制；不支持的格式可以明确选择作为普通文件发送。

** 媒体、通知和 Evil

静态图片使用缓存预览。动图和动态 QQ 表情在可用的 Canvas 行内宿主中播放；视频需
点击或按 ~RET~。发送 MP4 视频需要 ~ffmpeg~，视频正文和缩略图是独立资源。
验证码使用 ~browser-session~ 的隔离浏览器流程，不要求从 DevTools 手工复制 proof。

桌面通知和 mode line 都需显式开启：

#+begin_src emacs-lisp
(qq-notifications-mode 1)
(qq-mode-line-mode 1)
#+end_src

当前聚焦窗口正在显示目标聊天时不重复弹通知；静音与提及规则可在
~M-x customize-group RET qq-notifications RET~ 中设置。

Evil 已加载时使用包内集成，不要求 evil-collection。根页、联系人和群申请页用 ~gr~
刷新；根页和聊天用 ~g a~ 打开场景菜单。输入区的 ~RET~ 仍处理发送／补全；
聚焦草稿不会自动切换 Evil state。详细差异见手册。

* 开发与验证

依赖由 jjosh 和工作区源码登记管理，不使用 Eask。需要修改依赖时先导入完整上游历史，
再修改仓库内源码；不在构建阶段打私有补丁，也不以仓库外缓存作为修改归宿。

** 直接运行源码测试

下面的命令不读取日常 Emacs 的配置或包缓存。它按 registry 组装本地 load-path，使用
~dev-with-source-loads~ 避免旧 ~.elc~ 遮蔽源码，再运行聊天测试文件。先加载 ~qq~，让
运行时依赖在测试的交互保护之外完成初始化。

#+begin_src sh
emacs -Q --batch -L appkit-apps/emacs-dev -l dev --eval '
(let* ((collection (expand-file-name "appkit-apps"))
       (directories
        (cl-loop for (_ . entry) in dev-jjosh-package-registry
                 append
                 (let ((root (expand-file-name (plist-get entry :path)
                                               collection)))
                   (mapcar (lambda (path) (expand-file-name path root))
                           (plist-get entry :load-paths))))))
  (dev-with-source-loads directories
    (require (quote qq))
    (let ((result
           (dev-run-test-files
            (list (expand-file-name
                   "appkit-apps/emacs-qq/test/qq-chat-test.el")))))
      (prin1 result)
      (kill-emacs (if (zerop (plist-get result :unexpected)) 0 1)))))'
#+end_src

运行整个包的测试时，把上述文件列表替换为：

#+begin_src emacs-lisp
(directory-files (expand-file-name "appkit-apps/emacs-qq/test")
                 t "-test\\.el$")
#+end_src

测试使用隔离的账号状态，并可能关闭 QQ 视图或重置运行时；不要在登录了真实账号的
日常 Emacs 进程中直接运行整个测试集。批处理也不能代替图形媒体、补全窗口和真实
服务操作的验证。

** 交互开发与版本对照

在独立开发 Emacs 中加载 ~appkit-apps/emacs-dev/dev.el~ 后，可用 ~dev-definition~
读取 Lisp 定义，~dev-run-test-files~ 运行指定文件的测试。要查看已提交的某个版本：

#+begin_src emacs-lisp
(dev-jjosh-reload-package 'qq "@" 'source)
#+end_src

该操作需要 Majutsu／jjosh，读取指定提交的独立源码快照；不包含尚未 snapshot 的工作区
修改。它会卸载并重载相关 feature，不要用来热替换日常进程中的在线账号。
~elc~ 和 ~eln~ 加载方式用于独立产物对照，不截断开发主线。

* 源码导航

| 模块 | 职责 |
|------+------|
| ~qq.el~、~qq-runtime.el~ | 用户入口、账号上下文和视图生命周期 |
| ~qq-server.el~、~qq-rpc.el~ | WebSocket、认证、请求和事件 |
| ~qq-core.el~ | 界面调用的 QQ 操作层 |
| ~qq-account.el~、~qq-login.el~ | 账号状态和登录挑战 |
| ~qq-message.el~、~qq-state.el~、~qq-read.el~ | 消息、会话投影和已读状态 |
| ~qq-root.el~、~qq-chat.el~ | 账号／会话列表和聊天时间线 |
| ~qq-directory.el~、~qq-contacts.el~、~qq-user.el~、~qq-group.el~ | 联系人与资料 |
| ~qq-attachment.el~、~qq-resource.el~、~qq-remote-media.el~、~qq-media.el~ | 输入附件、原生资源和预览 |
| ~qq-forward.el~、~qq-completion.el~、~qq-transient.el~ | 转发、补全和动作菜单 |
| ~qq-notifications.el~、~qq-modes.el~、~qq-evil.el~ | 通知、mode line 和 Evil |

服务端的协议实现和账号持久化属于 ~ntqq-rs~。消息 ID 始终保留为原始十进制字符串，
不转换为数值；发送中的 ~local-*~ 占位在回执到达后晋升为服务端身份。
排查协议问题时保留原始字段类型，并对 token、账号、正文和媒体 URL 脱敏。
